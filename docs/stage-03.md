# שלב 3 — טעינה ראשונית באמצעות Python

## מה השתנה

רכיב Python מאמת את שני קובצי ה-CSV ומכניס אותם בטרנזקציה אחת ל-`VotesDb` ריק.
סקריפט ההפעלה מפעיל אותו לפני התחלת ה-API. מאגר שיש בו קלפיות ובוחרים נשמר
ללא שינוי, בלי לקרוא מחדש את קובצי המקור.

לפי אישור המשתמש, קובץ הדוגמה `Data/people.csv` נוקה: הוסרה העמודה הריקה,
וכל 40,000 הבוחרים הוגדרו כמי שטרם הצביעו, ללא זמן או מקום הצבעה. במקור היו
19,675 שורות שסומנו TRUE ללא זמן ומקום. זה היה תיקון חד-פעמי לנתוני הדוגמה,
לא התנהגות שמאפסת הצבעות בעת הפעלה. הטוען דוחה קובץ ראשוני עם רישומי הצבעה.

ערכי `PasswordHash` שבקובץ הקלפיות אינם מיובאים. קלפיות חדשות מקבלות `NULL`
בשדה זה עד שהמנהל יקבע סיסמאות בשלב ההתחברות. סיסמאות במאגר קיים נשמרות.

## הרצה

יש צורך ב-Python 3.10 ומעלה, .NET 8 ו-Docker Desktop. הבדיקות כאן בוצעו עם
Python 3.14. פתח PowerShell בתיקיית הפרויקט הראשית. `.env` משלב 1 צריך להתקיים.
להקמת Python בפעם הראשונה בלבד:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup-python.ps1
```

הסקריפט יוצר `.venv` מקומית ומתקין את החבילות מתוך `requirements.txt`.
אין צורך לבצע Activate. `.venv` וקובצי מטמון Python מוחרגים מ-Git.

אם ה-API עדיין פועל מהשלב הקודם, עצור אותו במסוף שלו באמצעות Ctrl+C לפני הרצה רגילה:

```powershell
docker compose up -d --wait
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/apply-schema.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run-api.ps1
```

למאגר ריק, ההפעלה תציג "הנתונים הוכנסו בהצלחה" ואז 130 קלפיות ו-40,000 בוחרים.
למאגר שכבר נטען, תוצג "המאגר הקיים נשמר; לא בוצעה טעינה מחדש."
ה-API נפתח לאחר סיום הטעינה ב-`http://127.0.0.1:5080`.

טעינה שנכשלה עוצרת את סקריפט ההפעלה לפני התחלת ה-API. `dotnet run` ישירות
אינו מפעיל את Python; נקודת ההפעלה הכוללת הנתמכת בשלב הזה היא `run-api.ps1`.
`docker compose up` לבדו מפעיל רק את MySQL.

## בדיקה עצמית

אימות קבצים בלבד, ללא חיבור למסד או שינוי בו:

```powershell
.\.venv\Scripts\python.exe tools/data_loader/main.py --validate
```

התוצאה הצפויה: "הקבצים תקינים: 130 קלפיות, 40000 בוחרים."

בדיקת הרשומות שנטענו:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/invoke-sql.ps1 -Query "SELECT COUNT(*) AS KalpiCount, SUM(PasswordHash IS NOT NULL) AS AssignedPasswords FROM Kalpi; SELECT COUNT(*) AS PeopleCount, SUM(Voted) AS VotedCount, SUM(VotedAt IS NOT NULL OR VotedIn IS NOT NULL) AS VoteDetails FROM People;"
```

התוצאה הצפויה במאגר הדוגמה החדש: 130 קלפיות, 0 סיסמאות מוגדרות,
40,000 בוחרים, 0 מצביעים ו-0 רשומות עם זמן או מקום הצבעה.

אפשר להפעיל שוב רק את רכיב האתחול:

```powershell
.\.venv\Scripts\python.exe tools/data_loader/main.py
```

הוא צריך לדווח על שימור המאגר הקיים. אפשר לפתוח גם את
`http://127.0.0.1:5080/health/db` ולראות שהחיבור תקין.

בדיקות אוטומטיות:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests/data_loader -p test_validation.py -v
.\.venv\Scripts\python.exe -m unittest discover -s tests/data_loader -p test_database.py -v
```

השנייה משתמשת בסיסמת root המקומית מתוך `.env` כדי ליצור מסד בדיקות בעל שם
אקראי `KalpiTechLoaderTest_...`. היא מוחקת רק את המסד שיצרה, ולא משנה את `VotesDb`.
הטוען הרגיל משתמש בחשבון `kalpitech`; שום סיסמה אינה מועברת כארגומנט לפקודה.

אם צריך להפעיל מופע בדיקה נוסף של API שכבר נבנה בלי לעצור שרת אחר:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run-api.ps1 -Port 5081 -NoBuild
```

`NoBuild` מיועד לבדיקה עם קוד שכבר נבנה; אחרי שינוי בקוד C# יש לבנות מחדש.

## אחריות הרכיבים

- `validation.py`: קריאת CSV בקידוד UTF-8, ניקוי רווחים חיצוניים ואימות שני הקבצים.
- `database.py`: בדיקת מצב המאגר, נעילת האתחול, כתיבה בטרנזקציה ו-Commit או Rollback.
- `main.py`: נקודת כניסה, קריאת הגדרות מקומיות והודעות הצלחה/כשל.
- `setup-python.ps1`: הקמת סביבת Python נפרדת לפרויקט.
- `run-api.ps1`: תיאום ההפעלה — קודם Python ואז ASP.NET Core.

האימות בודק עמודות בדיוק לפי שמות השדות; סדרן בקובץ אינו משנה. נבדקים שדות חובה,
אורכי מחרוזות לפי הסכמה, מזהי קלפי חיוביים בטווח INTEGER, כפילויות, תשע ספרות ASCII
בתעודת הזהות, סוגי קלפיות ושיוך כל בוחר לקלפי שבקובץ. מייל ריק הופך ל-NULL;
מייל שאינו תקין מבחינת כתובת נשמר, ובהמשך שירות המייל ידלג עליו לפי ה-README.
תעודת הזהות נשארת מחרוזת עם אפסים מובילים. נעשה שימוש במודול `csv`, כך שפסיקים,
מרכאות וגרש בשמות מטופלים כנתונים ולא כחלק מתחביר SQL.

## מדוע הטרנזקציה חשובה

הרכיב פותח טרנזקציה ונועל את שורת `ElectionSettings` באמצעות `FOR UPDATE`.
שתי הפעלות אתחול מקבילות ממתינות זו לזו: הראשונה טוענת, והשנייה רואה את המאגר
הקיים ומדלגת. לפני כתיבה כל הקבצים עוברים אימות. הקלפיות מוכנסות תחילה,
ואחריהן הבוחרים בקבוצות של 1,000 רשומות. כל הקבוצות עדיין שייכות לאותה טרנזקציה.

`Commit` מאשר את כל הטעינה. שגיאה לפניו גורמת ל-`Rollback`, כולל הקלפיות שכבר
הוכנסו. השאילתות פרמטריות: ערכי ה-CSV מועברים בנפרד מטקסט SQL.
כאשר החיבור נכשל בזמן Commit, אין להניח שהתגובה מוכיחה מה נשמר; ההפעלה הבאה
בודקת את המאגר ואינה דורסת אותו. הודעת הצלחה מודפסת רק אחרי Commit מוצלח.

מאגר חלקי, למשל קלפיות ללא בוחרים, אינו מושלם או נמחק אוטומטית: מוצגת שגיאה
והנתונים נשמרים לבדיקה. גם מאגר ריק עם מועד בחירות שכבר התחיל אינו נטען.
מנגנון הנעילה ישמש בסיס לתיאום פעולות הוועדה וההצבעה בשלבים הבאים; פעולות אלו
עדיין אינן ממומשות.

## מה נבדק ומה עוד לא

עברו 8 בדיקות אימות, כולל תרחישי משנה עבור שדות שגויים, ועוד 7 בדיקות מול MySQL.
נבדקו עברית וגרש, אפסים מובילים, ערכי ברירת מחדל, קבצים פגומים, כפילויות,
RollBack לאחר כשל יזום במסד, מאגר חלקי, מאגר ריק לאחר תחילת בחירות ושתי הפעלות
מקבילות. נבדק שמאגר קיים שומר הצבעות, גיבובי סיסמאות ומועדי בחירות גם כשקובצי
המקור חסרים. הקבצים האמיתיים עברו אימות ונטענו, והפעלה חוזרת שימרה אותם.
גם לאחר אתחול קונטיינר MySQL נשמרו 130 הקלפיות ו-40,000 הבוחרים, ורכיב האתחול
דילג על טעינה מחדש. נבדק שה-API בפורט הבדיקה 5081 החזיר הצלחה לאחר ההפעלה.
הרצת השרת הנוסף השתמשה ב-`NoBuild`, משום שהשרת הקיים החזיק את קובץ ההרצה;
קוד ה-C# לא השתנה בשלב זה. לבנייה רגילה יש לעצור קודם מופעים הפועלים מאותו פרויקט.

לא מומשו עדיין מסך טעינה יזומה, החלפת מאגר, הרשאות מנהל, התחברות או אישור הצבעה.
הטוען הנוכחי הוא כלי אתחול מקומי, ולא נתיב HTTP הפתוח למשתמשים.
