# שלב 7 — אישור הצבעה ושמירה אטומית

כפתור אישור שומר הצבעה בזמן פעילות הבחירות. השרת בודק מחדש את ההתחברות,
תפקיד הקלפי, השיוך בקלפי רגילה, מצב הבחירות ומצב Voted. הנתונים מהחיפוש
משמשים להצגה בלבד: הם אינם אישור שהבוחר עדיין רשאי להצביע בזמן השמירה.

## הרצה

עצור את השרת הקודם באמצעות Ctrl+C. בתיקיית הפרויקט הראשית:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run-api.ps1
```

פתח `http://127.0.0.1:5080/`. אין שינוי בסכמת המסד או בסיסמאות.
כפתור אישור זמין כשמצב הבחירות הוא פעילות; ההרשאה נאכפת שוב בשרת גם אם
תצוגת המצב טרם התעדכנה. ביטול אינו שולח בקשת שמירה ומשאיר את הבוחר ללא שינוי.
בזמן השמירה אישור, ביטול ויציאה מושבתים כדי שלא תתחיל פעולה נוספת באותו מסך.
לאחר התוצאה חוזרים לחיפוש עם שדה ריק והודעת הפעולה.

## תרגול ובדיקה עצמית במסד זמני

כדי לבדוק בלי לרשום הצבעות במאגר הפרויקט, הרץ:

```powershell
dotnet build src/KalpiTech.Api --no-restore -p:UseAppHost=false -o .local/stage07-build
.\.venv\Scripts\python.exe tests/votes/preview_vote.py
```

הסקריפט יוצר מסד זמני ובחירות פעילות לשעה ומדפיס כתובת מקומית נפרדת.
התחבר בכתובת הזאת לקלפי 1 (רגילה) או 2 (נגישה), עם הסיסמה הסינתטית
`SyntheticKalpiPassword-456`. אלה חשבונות בדיקה בלבד.

1. בקלפי 1 חפש `001234567`. לחץ ביטול וחפש שוב: מסך האישור צריך להיפתח שוב.
2. לחץ אישור: תוצג "ההצבעה נקלטה בהצלחה!" ותחזור לחיפוש.
3. חפש שוב אותו מזהה: תוצג "הצבעה כפולה! הבוחר כבר מימש את זכות הבחירה".
4. נסה `009876543` בקלפי 1: החיפוש ייחסם כי הבוחר משויך לקלפי אחרת.
5. כדי לבדוק הצבעה בפועל בקלפי נגישה של בוחר המשויך לקלפי 1, סיים את
   סביבת התרגול באמצעות Enter במסוף והפעל אותה מחדש. התחבר לקלפי 2
   ואשר את `001234567`. השיוך נשאר 1 ו-VotedIn יהיה 2.
6. בסיום לחץ Enter במסוף כדי לעצור את שרת התרגול ולנקות את מסד הבדיקה.

אישור בכתובת הרגילה של הפרויקט שומר רישום מתמשך במאגר הפעיל. אין פעולת
איפוס הצבעות. סביבת התרגול נועדה לאפשר בדיקות חוזרות בלי לשנות מאגר זה.

## איך השמירה מונעת הצבעה כפולה

`POST /api/voters/confirm` מקבל Id בלבד. מספר הקלפי נלקח מ-Claims המאומתים,
והזמן מ-TimeProvider בשרת. שליחת VotedIn, VotedAt או Role נוסף בגוף הבקשה
אינה משנה את הערכים שהשרת קובע.

VoteStore פותח טרנזקציה ונועל קודם את רשומת ElectionSettings, באותו סדר
שבו עובדים שינוי מועדים ואתחול Python. כך הפעולות מתואמות. לאחר מכן הוא
קורא את רשומת הבוחר עם FOR UPDATE ובודק את השיוך ומצב ההצבעה. זמן הפעילות
נבדק אחרי קבלת הנעילות: בקשה שהמתינה ובינתיים הבחירות הסתיימו נדחית.

העדכון מותנה בכך ש-Voted עדיין FALSE, ובקלפי רגילה גם בשיוך הנכון:

```sql
UPDATE People
SET Voted=TRUE, VotedAt=@now, VotedIn=@kalpi
WHERE Id=@id AND Voted=FALSE AND KalpiId=@kalpi;
```

בקלפי נגישה תנאי KalpiId אינו נכלל, אך מקום ההצבעה נשאר הקלפי המחוברת.
People.KalpiId אינו משתנה. VotedAt הוא זמן רישום ההצבעה ב-UTC.
כל שלושת שדות ההצבעה מתעדכנים יחד; הצלחה מוחזרת רק אחרי COMMIT.
יציאה מוקדמת מהפעולה או חריגה גורמות לביטול הטרנזקציה.
הסבר נעילות הרשומות מבוסס על [תיעוד MySQL 8.4](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html).

הנעילה המשותפת של ElectionSettings מסדרת כרגע גם הצבעות לבוחרים שונים
בתור קצר. זהו מבנה פשוט ללמידה ולתיאום עם טעינה; לא בוצעה בדיקת עומס
למספר גדול של קלפיות. שיפור מקביליות אפשרי בהמשך תוך שמירת כללי העקביות.

## אחריות הקבצים

| רכיב | אחריות |
| --- | --- |
| `Data/VoteStore.cs` | טרנזקציה, נעילות, בדיקות חוזרות ועדכון מותנה |
| `Models/VoteResult.cs` | תוצאת שמירה פנימית: הצלחה, זמן לא פעיל, חסר, שיוך או כפילות |
| `Controllers/VotersController.cs` | נתיב confirm, אימות Id והרשאת קלפי; מיפוי תוצאות להודעות |
| `Data/ElectionStore.cs` | קריאת מועדים משותפת גם בתוך טרנזקציית ההצבעה |
| `wwwroot/index.html` | כפתור אישור ותצוגת זמינות |
| `wwwroot/js/app.js` | שמירת הבוחר שנבחר, שליחה פעם אחת וחזרה לחיפוש |

אין ניסיון חוזר אוטומטי. אם התשובה אבדה ברשת, ייתכן שהשמירה כבר הושלמה;
חיפוש חוזר מאפשר לבדוק את המצב לפני פעולה נוספת. שגיאת מסד מחזירה
"השרת אינו זמין", והשרת אינו מדווח הצלחה ללא אישור השמירה.

## בדיקות שבוצעו ומה נשאר

```powershell
.\.venv\Scripts\python.exe -m pip install -r tests/election/requirements.txt
dotnet build src/KalpiTech.Api --no-restore -p:UseAppHost=false -o .local/stage07-build
.\.venv\Scripts\python.exe -m unittest discover -s tests/votes -p test_votes.py -v
```

הבנייה עברה ללא אזהרות ושגיאות. 37 בדיקות עברו: 27 הבדיקות מהשלבים הקודמים
ועשר בדיקות הצבעה. נבדקו שמירה רגילה ונגישה, מקור מקום וזמן ההצבעה,
הרשאות, CSRF, קלט, כפילות, שיוך וסיסמה שהשתנו לאחר החיפוש, חסימה לפני
ואחרי הפעילות, שימור לאחר אתחול ושגיאת מסד שגורמת ל-Rollback.
בבדיקה מקבילה שמונה בקשות לאותו בוחר הניבו הצלחה אחת ושבע דחיות;
נבדקה גם בקשה שחיכתה לנעילת בוחר וחצתה את מועד הסיום.
לאחר תיקון הכנת בדיקות המקביליות וזיהוי הנעילה, הבדיקה האחרונה הורצה שוב
באופן ממוקד ועברה. כל הנתונים נוצרו במסדים זמניים ונוקו בסיום.

בדפדפן נבדקו קלפי רגילה, ביטול ללא שינוי, חיפוש חוזר, אישור מוצלח וחסימת
בוחר שכבר הצביע. קלפי נגישה נבדקה מול ה-API; הממשק שלה, שינוי מצב בזמן
שמסך האישור פתוח ואובדן תשובה ברשת עדיין דורשים בדיקה ידנית.
לא בוצעו בדיקות עומס או ניתוק מסד בדיוק בזמן COMMIT.

שירות המייל עדיין אינו ממומש: הצלחת ההצבעה כעת מעידה על שמירתה במסד בלבד.
ספק המייל ופרטי השליחה ייקבעו בשלב המייל. טעינה יזומה ומעטפות כפולות
נשארות לשלבים הבאים.
