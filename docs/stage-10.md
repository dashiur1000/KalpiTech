# שלב 10 — נתוני השתתפות וגרפים

מסך הוועדה כולל **צפייה בנתונים**: מספר בוחרים, מספר מצביעים ואחוז השתתפות במאגר כולו, וחיפוש עיר עם השלמה וגרף השתתפות לכל עיר שנבחרה. המסך מתעדכן כל חמש שניות כשהוא פתוח.

הספירה בעיר מבוססת על `People.KalpiId` ו־`Kalpi.City`. הצבעה בקלפי אחרת, כולל מעטפה כפולה, נספרת בעיר השיוך. `VotedIn` אינו משמש לחישוב השתתפות לפי עיר. עיר שיש בה קלפי אבל אין בוחרים מוצגת עם ספירות אפס והנוסח "אין נתונים" במקום אחוז.

## הרצה ובדיקה ידנית

עצור את השרת הקיים ב־Ctrl+C והרץ מהתיקייה הראשית:

```powershell
./scripts/run-api.ps1
```

לא נוספה סכמת מסד בשלב הזה. אם טרם הרצת את עדכון שלב 8, הרץ קודם `./scripts/apply-schema.ps1`.

פתח http://127.0.0.1:5080 והתחבר כמנהל. לחץ **צפייה בנתונים**, בדוק את הספירות הכלליות ובחר עיר מתוך ההשלמה. ניתן לצפות בכל מצב בחירות. חזרה למסך הוועדה מפסיקה את בקשות הסטטיסטיקה; יציאה מנקה את נתוני המסך. קריאת הנתונים אינה משנה את המאגר.

## תרגול במסד זמני

```powershell
dotnet build src/KalpiTech.Api --output .local/stage10-build -p:UseAppHost=false
.venv/Scripts/python.exe tests/statistics/preview_statistics.py
```

אם תיקיית הבנייה הרגילה נעולה, אפשר לבנות עם תיקיית ביניים נפרדת:

```powershell
dotnet build src/KalpiTech.Api --output .local/stage10-build -p:UseAppHost=false -p:IntermediateOutputPath="$PWD/.local/stage10-obj/"
```

התרגול מדפיס כתובת זמנית ופרטי התחברות סינתטיים. השתמש בכתובת הזמנית בלבד:

1. התחבר ולחץ **צפייה בנתונים**. בתחילה יש ארבעה בוחרים ושני מצביעים, כלומר 50%.
2. בחר בית שמש: שני בוחרים, מצביע אחד ו־50%. אחד המצביעים הצביע בעיר אחרת ונספר בבית שמש לפי שיוכו.
3. בחר **עיר ללא בוחרים**: מוצגים אפס בוחרים, אפס מצביעים ו־"אין נתונים".
4. חזור לבית שמש. במסוף התרגול לחץ Enter פעם אחת. התרגול רושם מעטפה כפולה סינתטית בוועדת הבחירות (`0000`) לבוחר מבית שמש.
5. בלי לרענן את הדפדפן, המתן עד לעדכון הבא: ההשתתפות הכללית עולה ל־75%, בית שמש ל־100%, ובני ברק נשארת ב־50%. העיר שנבחרה נשמרת.
6. לחץ **חזרה למסך הוועדה**. בסיום לחץ Enter שוב במסוף כדי להסיר את המסד הזמני.

## אחריות הרכיבים

- `Participation.cs`: תוצאת ספירה ואחוז המחושב בצד השרת. אין חלוקה באפס; במקום אחוז ללא בוחרים מוחזר `null`. אחוזים מעוגלים לשתי ספרות לאחר הנקודה לצורך תצוגה.
- `StatisticsStore`: שאילתת SQL אחת שמסכמת בוחרים ומצביעים לפי עיר. `LEFT JOIN` כולל גם ערים ללא בוחרים. הסיכום הכללי מחושב מאותן תוצאות, כך שהסיכום והערים שייכים לאותה תמונת נתונים גם במהלך אישור הצבעה או החלפת מאגר.
- `StatisticsController`: נתיב `GET /api/statistics` המותר רק ל־Admin. השרת מחזיר ספירות, ערים וזמן עדכון UTC; אין מספרי זהות, שמות בוחרים, מיילים או סיסמאות. הגדרת `no-store` הקיימת מונעת שמירת תגובות API במטמון.
- HTML, CSS ו־JavaScript: שדה עיר עם `datalist`, ספירות וגרפי עמודה ללא ספרייה נוספת. כחול מסמן מצביעים ואפור מי שטרם הצביעו. מספרים וטקסט לצד הגרף מאפשרים להבין את הנתון בלי להסתמך רק על הצבע.

ההתחברות מוכיחה מי המשתמש; `[Authorize(Roles = "Admin")]` קובע אם הוא רשאי לצפות בנתונים. הסתרת הכפתור בקלפיות היא חלק מהממשק, והבדיקה המחייבת נעשית בשרת.

מנגנון הרענון מונע בקשות סטטיסטיקה חופפות ומתעלם מתשובה שהגיעה אחרי סגירת המסך. בחירת העיר נעשית מתוך רשימת הערים העדכנית. טקסט לא מוכר מציג בקשה לבחור עיר קיימת. אם העדכון נכשל, מוצגת הודעת כשל והבהרה שהנתונים הקודמים הם האחרונים שהתקבלו; אין הצגה של אפסים כאילו היו נתונים חדשים.

## בדיקות

```powershell
.venv/Scripts/python.exe tests/statistics/test_statistics.py
```

הבדיקות משתמשות במסד זמני ומריצות גם את בדיקות השלבים הקודמים. הבדיקות החדשות כוללות הרשאת מנהל בלבד, ספירה לפי שיוך גם כש־VotedIn בעיר אחרת, ערים ומאגר ללא בוחרים, אחוזי אפס ו־100 ועיגול 33.33%, היעדר פרטים אישיים, קריאה ללא שינוי נתונים, זמינות בכל מצבי הבחירות ועדכון לאחר אישור מעטפה כפולה.

בשלב זה עברו שבע בדיקות הסטטיסטיקה הממוקדות והבנייה הסתיימה ללא שגיאות או אזהרות. הרצה חוזרת של כל 66 הבדיקות הופסקה במהלך השיחה ולא התקבלה תוצאת סיום, ולכן אין כאן טענה שכל החבילה עברה מחדש. 59 בדיקות השלבים הקודמים עברו בסיום שלב 9.

בדפדפן נבדקו ספירות וגרפים, בחירת עיר, "אין נתונים", רענון אוטומטי אחרי הצבעה סינתטית, שימור העיר שנבחרה וחזרה למסך הוועדה. בדיקות עומס, ניתוק רשת בזמן רענון ושירות מייל לא נבדקו בשלב הזה. המאגר הפעיל לא שונה לצורך הבדיקות.
