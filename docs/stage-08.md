# שלב 8 — החלפת נתונים דרך מסך הוועדה

המנהל יכול לבחור שני קובצי CSV ולהחליף את הקלפיות והבוחרים. אין שינוי בחשבון המנהל או במועדי הבחירות.

## הרצה

עצור את השרת הקיים ב־Ctrl+C. מהתיקייה הראשית הרץ:

```powershell
./scripts/apply-schema.ps1
./scripts/run-api.ps1
```

פתח http://127.0.0.1:5080 והתחבר במייל vahadathabchirot@gmail.com ובסיסמה הקיימת. Docker ו־MySQL צריכים לפעול; סביבת Python שהוקמה בשלבים הקודמים נדרשת גם לטעינה דרך הממשק.

## בדיקה ידנית

לתרגול בלי להחליף את המאגר שלך אפשר להפעיל בחלון PowerShell נוסף:

```powershell
.venv/Scripts/python.exe tests/data_import/preview_import.py
```

הפקודה מדפיסה כתובת זמנית, פרטי התחברות סינתטיים ותיקייה עם `upload-kalpi.csv` ו־`upload-people.csv`. השתמש בשני הקבצים האלה במסך הזמני. בסיום חזור לחלון PowerShell ולחץ Enter כדי להסיר את מסד הבדיקה. כל התרגול מתבצע בנפרד מהמאגר שלך.

1. לחץ על **עדכון נתונים לבסיס הנתונים**. אם הטעינה נעולה או שיש הצבעות, מוצגת הסיבה ללא בחירת קבצים.
2. כשיש נתונים, אשר את אזהרת ההחלפה. ביטול משאיר את המאגר ללא שינוי.
3. בחר את `.local/import/kalpi.csv` הפרטי ואת `Data/people.csv` הנקי. הקבצים הללו יחליפו את כל הקלפיות והבוחרים; השתמש רק במאגר ללא הצבעות שאתה רוצה להחליף.
4. לחץ על **בדיקה וטעינת הנתונים**. לאחר הצלחה מופיע הנוסח "הנתונים הוכנסו בהצלחה" והטופס נסגר לאחר שלוש שניות.
5. התחבר לקלפי עם סיסמתה מהקובץ וחפש תעודת זהות ממנו. הפעלה מחדש צריכה לשמר את המאגר ואת הסיסמאות החדשות.
6. לבדיקה ללא שינוי המאגר, נסה עותק של קובץ הבוחרים עם תעודת זהות בת שמונה ספרות. השרת צריך לדחות אותו. אין לשנות קובץ מקור לצורך הבדיקה.

קובצי UTF-8 בלבד, עם או בלי BOM. קובץ Excel ששמו שונה ל־CSV אינו CSV ויש לייצא אותו תחילה. עד 5 MB לקלפיות ועד 20 MB לבוחרים.

עמודות קלפיות: `KalpiId,City,Place,Address,KalpiType,PasswordHash`. למרות השם, `PasswordHash` בקובץ מכיל סיסמה גלויה באורך 10–128 תווים; במסד נשמר גיבוב בלבד.

עמודות בוחרים: `Id,KalpiId,FirstName,LastName,Voted,EmailAddress,VotedAt,VotedIn`. כל הרשומות דורשות `FALSE` ושדות זמן ומקום ריקים. הסדר אינו מחייב; כל העמודות חייבות להופיע פעם אחת, ללא עמודה ריקה נוספת.

## אחריות הרכיבים

- `DataController`: מאפשר רק לחשבון Admin לקרוא את מצב הטעינה ולהעלות קבצים. מנגנון CSRF הקיים מגן גם על העלאה. השרת מתעלם משמות הקבצים שסיפק הדפדפן, משתמש בתיקייה אקראית תחת `.local/uploads` ומגַבב את הסיסמאות באמצעות `PasswordHasher`.
- `replace.py`: משתמש בבדיקות Python הקיימות לשני הקבצים, ואז נועל את רשומת הגדרות הבחירות ובודק שוב את הזמן ואת קיום ההצבעות. רק אז הוא מוחק ומכניס נתונים, כולל גיבובים, בטרנזקציה אחת. כשל לפני Commit משחזר את המאגר הקודם.
- `DataImportState`: סימון שנשמר יחד עם הטעינה. לאחר טעינה דרך המסך, המאגר הוא מקור הסיסמאות בעליית השרת; קובץ האתחול המקומי הישן אינו דורס אותן. ייבוא סיסמאות מפורש באמצעות `--import-kalpi-passwords` עדיין קיים ככלי מקומי.
- HTML ו־JavaScript: מציגים את האזהרה, בחירת הקבצים והודעות התוצאה. `FormData` שולח קבצים ב־multipart; ההרשאות והנעילה נאכפות מחדש בשרת ולא מסתמכות על המסך.

נשמרים גיבובים בלבד במסד. הקבצים הגלויים והגיבובים הזמניים נמחקים בסיום הבקשה ולא נכנסים ל־Git או ללוגים. עצירה פתאומית של תהליך השרת עלולה להשאיר תיקיית העלאה מקומית; אין מנגנון ניקוי אוטומטי לאחר קריסה בשלב זה.

נעילת 36 השעות חלה גם אם פעילות הקלפיות כבר הסתיימה. לאחר פקיעתה מותר להחליף רק מאגר ללא הצבעות. הנעילה משותפת לטעינה, שינוי מועדים ואישור הצבעה, ולכן בדיקות נעשות גם אחרי המתנה לבקשה אחרת.

לא מבטלים טרנזקציה שכבר רצה בגלל סגירת הדפדפן. אם התגובה אבדה, ייתכן שהשמירה הצליחה; בדוק את המאגר לפני ניסיון נוסף. אין ניסיונות טעינה חוזרים אוטומטיים.

## בדיקות אוטומטיות

```powershell
dotnet build src/KalpiTech.Api --output .local/stage08-build -p:UseAppHost=false
.venv/Scripts/python.exe tests/data_import/test_import.py
.venv/Scripts/python.exe -m unittest discover -s tests/data_loader -p test_validation.py
```

בדיקות ה־HTTP משתמשות במסד MySQL זמני ובנתונים סינתטיים, ומנקות אותו בסוף. נבדקות הרשאות, CSRF, אישור ההחלפה, קבצים שגויים, נעילת זמן, מאגר עם הצבעות, גיבוב והתחברות, שימור לאחר הפעלה מחדש, Rollback לאחר כשל באמצע, שתי טעינות מקבילות ובדיקת זמן לאחר המתנה לנעילה. כל בדיקות ההתחברות, החיפוש, המועדים ואישור ההצבעה מהשלבים הקודמים כלולות.

עברו 49 בדיקות API ו־9 בדיקות תקינות קבצים. בדפדפן נבדקו התחברות, אזהרת ההחלפה, הצגת הטופס וביטולו; העלאה ושמירה בפועל נבדקו דרך HTTP אוטומטי. לא בוצעה החלפה של המאגר הפעיל לצורך בדיקות. בדיקות עומס, קריסת מחשב ושירות מייל אינן חלק משלב זה.
