# שלב 6 — מועדי הבחירות ומצב המערכת

המנהל קובע התחלה וסיום לפי שעון ישראל. השמירה ב-UTC בטבלת ElectionSettings
הקיימת; אין שינוי סכמה. המועדים נשמרים לאחר אתחול. ניתן לעדכן אותם רק לפני
ההתחלה, לפי החלטת המשתמש. אי אפשר לקבוע התחלה בעבר או סיום שאינו אחרי ההתחלה.

## הרצה ובדיקה עצמית

עצור את השרת הקודם במסוף שלו באמצעות Ctrl+C. מתיקיית הפרויקט:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run-api.ps1
```

פתח `http://127.0.0.1:5080/` והתחבר כמנהל עם הסיסמה הנוכחית.
במסך מופיעים מצב הבחירות וטופס קביעת מועדים. הזן התחלה בעתיד וסיום מאוחר ממנה,
לחץ שמירה ואשר את החלונית. בדוק שהשעות המוצגות תואמות למה שהזנת.
לפני ההתחלה ניתן לעדכן את המועדים. נסה סיום מוקדם מההתחלה ובדוק שהבקשה נדחית.
רענן את העמוד והפעל את השרת מחדש: המועדים צריכים להישמר.
קלפי מחוברת רואה את המצב והמועדים, אך אינה רשאית לקבוע אותם.

כדי לתרגל מעבר מצבים ונעילה בלי לקבוע מועדים קצרים במאגר הפרויקט,
אפשר להפעיל סביבת תרגול נפרדת לאחר בניית גרסת הבדיקה:

```powershell
dotnet build src/KalpiTech.Api --no-restore -p:UseAppHost=false -o .local/stage06-build
.\.venv\Scripts\python.exe tests/election/preview_schedule.py
```

הסקריפט מדפיס כתובת ופרטי חשבון סינתטי, ומשתמש במסד זמני. שם אפשר לקבוע
התחלה בעוד כמה דקות וסיום דקה אחריה. השאר את העמוד פתוח: מצב הכנה יתחלף
לפעילות ולאחר מכן לסיום; שדות המועדים יינעלו בהתחלה. חלון הוועדה נשאר פתוח
גם אחרי הסיום, עד 36 שעות מההתחלה. לחץ Enter במסוף בסיום כדי לנקות את הסביבה.
אין פונקציית איפוס יום בחירות; לאחר התחלת הבחירות המועדים במאגר הפעיל נעולים.

## כללי הזמן

| זמן השרת | מצב / התנהגות |
| --- | --- |
| לא נקבעו מועדים, או לפני StartsAt | הכנה; ניתן לקבוע מועדים |
| StartsAt ועד לפני EndsAt | פעילות |
| EndsAt ואילך | סיום |
| StartsAt ועד לפני StartsAt + 36 שעות | טעינה נעולה; חלון מעטפות כפולות פתוח |
| בדיוק StartsAt + 36 שעות ואילך | חלון מעטפות כפולות סגור; נעילת הזמן לטעינה פוקעת |

האיסור להחליף מאגר המכיל הצבעות חל גם אחרי חלון הזמן.
חלון הוועדה אינו תלוי במועד סיום ההצבעה בקלפיות.
הממשק מתעדכן כל חמש שניות. ההחלטות העסקיות משתמשות בזמן השרת בכל בקשה,
כך שתצוגה שטרם התעדכנה אינה משנה את כללי הזמן.

## אחריות הרכיבים

| קובץ | אחריות |
| --- | --- |
| `Models/ElectionSchedule.cs` | חישוב מצב וחלון 36 שעות מתוך מועדי UTC |
| `Contracts/ElectionScheduleRequest.cs` | שדות StartsAt ו-EndsAt כשעות ישראל מקומיות |
| `Services/IsraelTime.cs` | המרה בין שעון ישראל ו-UTC, כולל שעון קיץ |
| `Data/ElectionStore.cs` | קריאה ושמירה בטרנזקציה עם נעילת רשומת ההגדרות |
| `Controllers/ElectionController.cs` | קריאה למשתמש מחובר; שמירה למנהל בלבד ואימות המועדים |
| `wwwroot/index.html`, `wwwroot/js/app.js` | טופס, חלונית אישור ותצוגת מצב מתעדכנת |

`GET /api/election` מחזיר מועדי UTC, מועדי ישראל ומצב מחושב. הפעולה דורשת
התחברות. `POST /api/election/schedule` דורש תפקיד Admin ואסימון CSRF.
הקלט בפורמט `yyyy-MM-ddTHH:mm` ללא אזור זמן; השרת מפרש אותו במפורש כשעון ישראל.
שעה שלא קיימת במעבר לשעון קיץ או שחוזרת פעמיים במעבר לשעון חורף נדחית,
כדי למנוע בחירה שקטה של מועד לא חד-משמעי.

השרת משתמש ב-[TimeProvider.System](https://learn.microsoft.com/en-us/dotnet/api/system.timeprovider?view=net-8.0)
לקבלת זמן UTC. State אינו שדה שנשמר ומתעדכן: הוא תוצאה של השוואת זמן השרת
למועדים השמורים. לכן אין צורך בתהליך רקע כדי לעבור אוטומטית בין המצבים.

לפני שינוי המועדים, ElectionStore נועל את הרשומה באמצעות SELECT FOR UPDATE,
קורא את המועדים הנוכחיים ובודק את זמן השרת אחרי קבלת הנעילה. בקשות מקבילות
ואתחול Python משתמשים באותה רשומה לתיאום. LoadLockedUntil ממשיך להיות שדה
מחושב במסד, ולא ערך שהמנהל יכול להזין בנפרד.

## בדיקות ותכולת השלב

```powershell
.\.venv\Scripts\python.exe -m pip install -r tests/election/requirements.txt
dotnet build src/KalpiTech.Api --no-restore -p:UseAppHost=false -o .local/stage06-build
.\.venv\Scripts\python.exe -m unittest discover -s tests/election -p test_election.py -v
dotnet build tests/election/ClockChecks -p:UseAppHost=false
dotnet tests/election/ClockChecks/bin/Debug/net8.0/ClockChecks.dll
```

הבנייה עברה ללא אזהרות ושגיאות. כל 27 בדיקות ה-API עברו במסד זמני:
22 בדיקות התחברות וחיפוש, וחמש בדיקות מועדים, הרשאות, CSRF, UTC במסד,
קלט לא תקין, נעילה אחרי התחלה, פעילות וסיום, חלון הוועדה ושימור לאחר אתחול.
17 בדיקות נוספות בדקו את הגבולות המדויקים ואת המרת שעות החורף והקיץ בישראל.
בדפדפן נבדקו התחברות, מצב הכנה, מילוי ושמירת מועדים והצגתם בשעון ישראל.
ביטול חלונית השמירה ומעבר מצבים בזמן שהדפדפן פתוח עדיין דורשים בדיקה ידנית.

השלב מספק את מצב הבחירות והזמנים. כפתור אישור הצבעה עדיין מושבת ואין נתיב
שמירת הצבעה. טעינה יזומה ומעטפות כפולות טרם מומשו; בעת מימושן הן יבדקו את
המצב בשרת בתוך פעולת השמירה. `loadLocked` ו-`doubleEnvelopesAllowed` כעת
מתארים את חלונות הזמן ואינם הרשאה לבצע פעולה שטרם קיימת.
