# עדכון — מייל הוועדה וסיסמאות קלפיות מקובץ CSV

מייל ההתחברות למנהל הוא `vahadathabchirot@gmail.com`. המייל עודכן גם במסד
המקומי וגם ב-.env. סיסמת המנהל הנוכחית נשמרה; אין פעולת החלפת סיסמה בממשק
או ב-API. שינוי המייל מבטל התחברות קיימת עם המזהה הישן בבקשה הבאה.
הכתובת היא שם התחברות; ספק המייל וכתובת השולח טרם נקבעו.

## הקובץ שהמשתמש יספק

לפי החלטת המשתמש, שם העמודה בקובץ הקלפיות נשאר PasswordHash. הכותרת הנדרשת:

```csv
KalpiId,City,Place,Address,KalpiType,PasswordHash
```

שמור את הקובץ המלא בקידוד UTF-8 ב-`.local/import/kalpi.csv`. הוא נשאר קובץ
הקלפיות באותו מבנה, עם שם העמודה PasswordHash; אין צורך בקובץ סיסמאות
נפרד. התיקייה .local מוחרגת מ-Git. אל תכניס סיסמאות אמיתיות ל-Data/kalpi.csv
הקיים: זהו קובץ דוגמה שכבר נמצא ב-Git.

הקובץ חייב לכלול בדיוק את כל מספרי הקלפיות שבמאגר, ללא כפילויות. הסיסמאות
נדרשות להכיל 10 עד 128 תווים ללא תווי בקרה, בהתאם לסיסמאות שסיפק ואישר המשתמש.
פסיקים ומירכאות נתמכים לפי כללי CSV. רווחים בסיסמה נשמרים כפי שהם.
למרות השם PasswordHash, העמודה בקובץ מכילה סיסמאות גלויות. השרת מקבל את
הסיסמה ויוצר את הגיבוב. במסד PasswordHash מכיל את הגיבוב בלבד.

הקובץ שסופק בשם kalpi.csv היה בפועל קובץ Excel. הוא הומר ל-CSV בקידוד UTF-8,
עם 130 קלפיות ושמירה מדויקת של ערכי הסיסמאות. מספרי קלפיות מספריים מ-Excel
נכתבו כמספרים שלמים. הקובץ המקורי בתיקיית Downloads נשמר ללא שינוי.
קובץ הדוגמה ב-Data מכיל כעת ערכי SampleOnly סינתטיים, ואינו מקור לסיסמאות
האמיתיות. ההחרגה של .local מ-Git אומתה.

## הפעלה והתנהגות

עצור את השרת הקודם באמצעות Ctrl+C והפעל מהתיקייה הראשית:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run-api.ps1
```

פתח `http://127.0.0.1:5080/` והתחבר עם המייל המעודכן וסיסמת המנהל הנוכחית.
שתי פעולות ניהול הסיסמאות אינן מופיעות. הנתיבים `/api/auth/kalpi-password`
ו-`/api/auth/admin-password` הוסרו ומחזירים 404 בגרסה החדשה.

לפני טעינה יזומה ראשונה, בעת הפעלת השרת KalpiPasswordImporter קורא את הקובץ הפרטי, מאמת את המבנה,
המזהים והסיסמאות, ונועל את רשומות המסד בטרנזקציה. הוא מאמת כיסוי מלא של
הקלפיות לפני שינוי ומגבש סיסמאות באמצעות PasswordHasher המובנה ב-ASP.NET.
הוא משנה PasswordHash בלבד: בוחרים, הצבעות, שיוכים ומועדים אינם משתנים.
אם קובץ שנמצא אינו תקין, ההפעלה נכשלת בלי לעדכן סיסמאות באופן חלקי.
אם הקובץ חסר, ההפעלה ממשיכה עם הסיסמאות הקיימות ומדווחת על כך בלוג.

סיסמה שונה מחליפה את הגיבוב ומבטלת התחברויות ישנות של אותה קלפי.
סיסמה שלא השתנתה משמרת את הגיבוב וכרטיסי ההתחברות, גם לאחר הפעלה מחדש.
בלוג נכתב רק מספר החשבונות שהשתנו, ללא סיסמאות, שורות CSV או גיבובים.

במאגר ריק, run-api.ps1 מעביר את הקובץ הפרטי גם לרכיב Python לטעינת פרטי
הקלפיות. Python מאמת את עמודת PasswordHash אבל אינו שומר אותה במסד. C# שומר
את גיבובי הסיסמאות לפני שה-API מתחיל לקבל בקשות. במאגר קיים פרטי הקלפיות
והבוחרים נשמרים; מתבצעת רק טעינת הסיסמאות בעת עליית C#.

## אחריות הרכיבים והבדיקות

- `Data/KalpiPasswordImporter.cs`: פענוח CSV, אימות וטעינת גיבובים אטומית.
- `AccountStore.cs`: התחברות ואתחול מנהל; פעולות שינוי הסיסמאות הוסרו.
- `AuthController.cs`: התחברות, יציאה, זהות ו-CSRF; אין נתיבי ניהול סיסמאות.
- `tools/data_loader`: אימות מבנה PasswordHash וטעינת פרטי קלפיות בלבד.
- `Program.cs`: הפעלת טעינת הסיסמאות לפני פתיחת השרת.

לבנייה ובדיקות מול מסדים זמניים בלבד:

```powershell
dotnet build src/KalpiTech.Api --no-restore -p:UseAppHost=false -o .local/password-csv-build
.\.venv\Scripts\python.exe -m unittest discover -s tests/password_csv -p test_password_csv.py -v
.\.venv\Scripts\python.exe -m unittest discover -s tests/data_loader -p test_validation.py -v
```

בדיקות ה-CSV כוללות טעינת גיבובים והתחברות, ביטול Cookie לאחר שינוי סיסמה,
שימור Cookie וגיבוב כאשר הסיסמה זהה, קובץ חסר/כפול/קלפי זרה/סיסמה קצרה,
CSV מצוטט ופגום ואימות שלא מופיעות סיסמאות בלוג. בדיקות ההתחברות וההצבעה
הותאמו להסרת פעולות ניהול הסיסמאות. הקובץ האמיתי עבר בדיקת מבנה ומזהים
עם 130 קלפיות ו-40,000 בוחרים. התאמת הסיסמאות בפועל נבדקת בטעינה חוזרת:
כאשר כל סיסמה תואמת לגיבוב במסד, מספר החשבונות שהשתנו הוא אפס.

הבנייה עברה ללא אזהרות ושגיאות. 41 בדיקות API וייבוא עברו, לצד תשע בדיקות
אימות CSV ב-Python. בדיקת הלוג הורצה שוב באופן ממוקד אחרי תיקון קידוד
הקריאה בבדיקת Windows. מייל החשבון במסד המקומי אומת עם גיבוב ללא שינוי.

לאחר אישור המשתמש נטענו למסד גיבובים עבור כל 130 הקלפיות. טעינה חוזרת
אימתה התאמה של כל הסיסמאות והחזירה אפס חשבונות שהשתנו. השוואת חתימות
לפני ואחרי הייבוא אימתה ש-40,000 הבוחרים, כל רישומי ההצבעה, פרטי הקלפיות,
מועדי הבחירות וחשבון המנהל נשמרו ללא שינוי. שם העמודה בקובץ נשאר PasswordHash.
