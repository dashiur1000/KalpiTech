# שלב 12 — Docker ותרחיש הדגמה מלא

בכל מחשב מופעל עותק עצמאי, עם מאגר מקומי משלו. אין סנכרון בין מחשבים.
להפעלת המערכת דרוש Docker עם Linux containers ו־Docker Compose; אין צורך להתקין .NET או Python במחשב המארח.
הבנייה הראשונה דורשת אינטרנט להורדת התמונות והתלויות. שליחת מייל דורשת אינטרנט גם בזמן העבודה.

## אחריות הקבצים

- `Dockerfile` בונה את שרת .NET 8 ומצרף את Python ואת רכיב טעינת הנתונים. התהליך פועל כמשתמש רגיל.
- `.dockerignore` מאפשר לבנייה לקבל רק קוד נחוץ; `.env`, קובצי CSV וקבצים פרטיים אינם נכללים בתמונה.
- `compose.yaml` מפעיל MySQL, כפי שהיה עד כה.
- `compose.app.yaml` מוסיף את השרת, מחכה לבריאות MySQL ומחבר תיקיות קלט לקריאה בלבד.
- `docker/start.py` מקים טבלאות חסרות, טוען רק מאגר ריק ואז מפעיל את השרת. מאגר קיים נשמר.
- `mysql_data` שומר את המסד; `app_state` שומר מפתחות הגנת Cookie וקובצי עבודה. ב־Linux המפתחות אינם מוצפנים באמצעות Windows DPAPI; יש לשמור על פרטיות קובצי Docker במחשב.
- `MYSQL_HOST` מאפשר לשרת ול־Python להתחבר לשירות `mysql` ברשת Docker; בהרצה המקומית הישנה ברירת המחדל נשארה `127.0.0.1`.

## הפעלה במחשב הנוכחי

עצור תחילה את שרת .NET המקומי אם הוא תופס את פורט 5080. אין צורך לעצור או למחוק את MySQL הקיים.
מהתיקייה הראשית:

```powershell
New-Item -ItemType Directory -Force .local/import | Out-Null
docker compose -f compose.yaml -f compose.app.yaml up -d --build --wait
```

פתח http://127.0.0.1:5080 ובדוק גם http://127.0.0.1:5080/health/db.
הפקודות משתמשות במאגר `kalpitech` הקיים ובסיסמת המנהל שכבר שמורה בו.
אם 5080 תפוס, אפשר להוסיף ל־`.env` למשל `APP_PORT=5081` ולפתוח את הכתובת עם הפורט הזה.

לעצירה בלי מחיקת נתונים:

```powershell
docker compose -f compose.yaml -f compose.app.yaml down
```

הפעלה מחדש: אותה פקודת `up`. אין להוסיף `--volumes` לעצירה של העותק שלך: אפשרות זו מוחקת את המאגר ואת מפתחות ההתחברות.

## הכנת מחשב אחר

1. התקן Docker Desktop, הפעל אותו במצב Linux containers והעבר את תיקיית הפרויקט.
2. צור `.env` מתוך `.env.example` אם אינו קיים. הגדר סיסמאות מסד פרטיות ואת `ADMIN_INITIAL_PASSWORD`: 4–128 תווים, ללא ערך הדוגמה. המשתמש של המנהל הוא `ADMIN_EMAIL`.
3. מאגר חדש יוצר מנהל לפי ערך האתחול. סיסמת המנהל המעודכנת במחשב המקורי אינה מועתקת עם הקוד או התמונה. שינוי ערך האתחול אינו משנה מנהל שכבר קיים.
4. ודא שיש `Data/people.csv` ו־`Data/kalpi.csv`. להעברת סיסמאות הקלפיות שלך, העבר בנפרד את `.local/import/kalpi.csv`. צור את תיקיית `.local/import` גם אם תבחר להעלות קבצים דרך מסך המנהל בהמשך. קובץ זה מכיל סיסמאות גלויות ואינו מיועד ל־Git.
5. להדגמה ללא מייל, השאר `MAIL_ENABLED=false`. להפעלת Brevo, הגדר מקומית את המפתח והשולח לפי מדריך שלב 11.
6. הרץ את פקודת `up` שלמעלה ופתח את הדפדפן. כל הכתובות מוגבלות למחשב המקומי.

התמונה אינה מכילה את הנתונים מהמסד המקורי. במחשב אחר מועדי הבחירות מתחילים ללא הגדרה, והבוחרים נטענים מקובצי הקלט. השתמש בנתונים סינתטיים לצורך הדגמה.

## תרחיש להצגה ידנית

יש לבצע על עותק הדגמה נפרד עם בוחרים סינתטיים שטרם הצביעו. אין אפשרות לאפס הצבעות דרך הממשק.

1. התחבר כמנהל, העלה את שני קובצי ה־CSV ובדוק הודעת הצלחה. ודא שבמסך הנתונים מספר הבוחרים מתאים לקובץ.
2. קבע התחלה בעוד מספר דקות וסיום לאחר ההתחלה. לפני ההתחלה בדוק שלא ניתן לאשר הצבעה.
3. לאחר ההתחלה התחבר לקלפי רגילה בחלון פרטי, חפש בוחר משויך ואשר. בדוק הודעת הצלחה; חיפוש חוזר מציג הודעת הצבעה כפולה.
4. בחלון פרטי אחר התחבר לקלפי נגישה ואשר בוחר אחר ששויך לקלפי רגילה. כך אפשר להסביר את ההבדל בין שיוך הבוחר למקום ההצבעה בפועל.
5. כמנהל, אשר מעטפה כפולה לבוחר נוסף בלי מספר קלפי. מקום הרישום הוא `0000 — ועדת הבחירות`.
6. בדוק שמספר המצביעים בסטטיסטיקה גדל בשלוש ושטעינת נתונים נעולה לאחר תחילת הבחירות.
7. עצור באמצעות `down`, הפעל שוב ובדוק שההצבעות, המועדים וסיסמאות הקלפיות נשמרו. אפשר לבצע חיפוש חוזר לבוחר שכבר הצביע.
8. לאחר סיום הבחירות, אישור בקלפי נחסם; הוועדה עדיין יכולה להזין מעטפות עד 36 שעות מההתחלה. אין לשנות את שעון המחשב כדי להדגים זאת — הבדיקה האוטומטית מגיעה למצבים אלה במסד זמני בלבד.

## בדיקה אוטומטית מבודדת

למפתח בלבד, עם סביבת Python של הפרויקט:

```powershell
docker compose -f compose.yaml -f compose.app.yaml build api
.\.venv\Scripts\python.exe tests/docker/test_demo.py
```

הבדיקה יוצרת פרויקט Compose בשם ייחודי, פורטים פנויים, קבצים סינתטיים ומאגר נפרד. היא אינה קוראת את `.env` הפרטי או את קובצי הבוחרים והסיסמאות שלך, ומייל כבוי.
היא בודקת אתחול, העלאה דרך Python בתוך הקונטיינר, Authentication ו־Authorization, קביעת מועדים, הצבעות רגילות ונגישות, כפילויות, מעטפות לאחר הסיום, חלון 36 שעות, סטטיסטיקה והקמה מחדש תוך שימור נתונים ו־Cookie. בסיום נמחקים רק הקונטיינרים והכרכים של הבדיקה.

הבדיקה פועלת ב־Linux containers על המחשב הנוכחי; הפעלה במחשב פיזי נוסף ומסירת מייל אמיתי ממנו דורשות בדיקה נפרדת. תצוגת הדפדפן לא נבדקת מחדש בתרחיש ה־API הזה.

תוצאות השלב: בניית התמונה ותרחיש Docker המלא עברו, כולל יצירה מחדש של שני הקונטיינרים ושימור Cookie. כל 16 בדיקות רכיב הטעינה עברו. קונטיינרי הבדיקה והכרכים הזמניים נוקו; העותק הקיים לא הופעל מחדש לצורך הבדיקה.

מקורות טכניים: [סדר הפעלה ובריאות ב־Compose](https://docs.docker.com/compose/how-tos/startup-order/), [תמונות .NET 8 ומשתמש רגיל](https://learn.microsoft.com/en-us/dotnet/core/whats-new/dotnet-8/containers).
