# שלב 11 — מייל אישור ותצוגת תוצאות

לאחר אישור מוצלח בקלפי או בוועדה, השרת מבצע ניסיון שליחה יחיד דרך Brevo. נושא המייל הוא בדיוק **"וועדת הבחירות המרכזית - אישור הצבעה"**. גוף ההודעה הוא בדיוק:

> שלום {FirstName} {LastName}, הצבעתך נקלטה בהצלחה!

הניסיון מתחיל אחרי Commit בלבד. כתובת חסרה או לא תקינה מדולגת. תשובת כשל מהספק או פקיעת זמן ההמתנה אינן מבטלות את ההצבעה ואינן גורמות לניסיון חוזר. זמן ההמתנה המרבי לספק הוא חמש שניות. הודעת ההצלחה במסך מעידה על שמירת ההצבעה; היא אינה אישור שהמייל הגיע לתיבה.

הודעות הצלחה מוצגות בירוק והודעות כשל באדום בראש המסך, עם גלילה אל ההודעה ושמירת הנוסחים המחייבים. הצבעה כפולה בחיפוש או באישור מוצגת גם בחלונית עם כפתור "סגירה", בקלפיות ובוועדה. במעטפה כפולה הוסר שדה מספר הקלפי: השרת שומר `VotedIn=0`, המוצג כ־`0000 — ועדת הבחירות`, בלי לשנות את שיוך הבוחר.

## הפעלה רגילה

עצור את השרת ב־Ctrl+C והרץ מהתיקייה הראשית:

```powershell
./scripts/run-api.ps1
```

פתח http://127.0.0.1:5080 ורענן ב־Ctrl+F5 כדי לטעון את קובצי הממשק המעודכנים. אין שינוי סכמה נוסף ואין איפוס נתונים או סיסמאות. המייל מוגדר ככבוי עד להשלמת ההגדרות אצל הספק.

## הגדרת Brevo

1. פתח חשבון ב־[Brevo](https://www.brevo.com/), והשלם את הפעלת שירות המייל בהתאם להנחיות בחשבון.
2. בהגדרות **Senders, Domains, IPs > Senders**, הוסף שולח בשם `ועדת הבחירות` ובכתובת `vahadathabchirot@gmail.com`. הזן ב־Brevo את קוד האימות שנשלח לתיבה. [הוראות אימות השולח](https://help.brevo.com/hc/en-us/articles/208836149-Create-a-new-sender-From-name-and-From-email).
3. צור מפתח API לחשבון בהתאם ל-[מדריך המפתחות](https://developers.brevo.com/docs/api-key-authentication). המפתח הוא הרשאה של השרת לפנות ל־Brevo; הוא אינו סיסמת המנהל ואינו מועבר לדפדפן. אין לשלוח אותו בצ'אט.
4. ערוך מקומית את `.env`, המוחרג מ־Git. החלף רק את ארבע הגדרות המייל:

```dotenv
MAIL_ENABLED=true
MAIL_SENDER_EMAIL=vahadathabchirot@gmail.com
MAIL_SENDER_NAME=ועדת הבחירות
MAIL_API_KEY=המפתח_הפרטי_שיצרת
```

השורה האחרונה היא מציין מקום להסבר, ולא מפתח שניתן להשתמש בו. שמור את הקובץ כ־UTF-8; אין צורך במירכאות. השאר `MAIL_ENABLED=false` כל עוד השולח או המפתח אינם מוכנים.

5. הפעל מחדש באמצעות `run-api.ps1`. בזמן אישור הצבעה מוצלח של בוחר בעל מייל תקין, נשלחת הבקשה ל־Brevo. בדוק בתיבה וביומן המיילים של הספק אם המייל התקבל. אל תאשר בוחר במאגר הפעיל רק לצורך בדיקה, שכן האישור הוא רישום הצבעה אמיתי במערכת.

כתובת Gmail חינמית אינה מאפשרת אימות דומיין בבעלותך. Brevo מתעד שהוא מחליף כתובת שולח חינמית בכתובת מסירה משלו; לכן הכתובת שתוצג לנמען עשויה להיות שונה ממייל הוועדה שהוגדר. [הסבר Brevo על החלפת כתובת השולח](https://help.brevo.com/hc/en-us/articles/14925263522578-Comply-with-Gmail-Yahoo-and-Microsoft-s-requirements-for-email-senders).

## תרגול ללא מייל אמיתי

```powershell
dotnet build src/KalpiTech.Api --output .local/stage11-build -p:UseAppHost=false -p:IntermediateOutputPath="$PWD/.local/stage11-obj/"
.venv/Scripts/python.exe tests/email/preview_email.py
```

הסקריפט יוצר מסד זמני ומדמה API מקומי של Brevo. הוא מדפיס כתובת ופרטי התחברות סינתטיים. הבוחרים במאגר שלך אינם משתנים, ולא נשלח מייל החוצה.

1. התחבר כמנהל הסינתטי בכתובת הזמנית בלבד ולחץ **הזנת מעטפות כפולות**.
2. חפש `001234567`. בדוק שהשיוך הוא קלפי 1, מקום הרישום הוא `0000`, ואין שדה להזנת מספר קלפי.
3. לחץ אישור. מתקבלת הודעת הצלחה ירוקה במסך הוועדה.
4. חפש שוב את אותו בוחר. מתקבלת חלונית הצבעה כפולה עם הנוסח המחייב. לחץ "סגירה": ההודעה האדומה נשארת במסך, ורישום ההצבעה אינו משתנה.
5. לחץ Enter במסוף. התוצאה הצפויה היא `(1, 1, True, 0)` וניסיון מייל מדומה אחד. המסד הזמני נמחק.

כדי לתרגל אישור קלפי במקום מעטפה כפולה, הפעל מחדש את התרגול, התחבר לקלפי הסינתטית 1 וחפש את אותו מספר זהות. מקום ההצבעה במקרה זה יישמר כ־1. אין צורך לשנות את המועדים במאגר הפעיל.

## אחריות הקוד

- `VoteStore` ממשיך לטפל בטרנזקציה ובמניעת כפילויות. הוא קורא גם את שם הבוחר והמייל בתוך הטרנזקציה, ומחזיר את פרטי הנמען רק לאחר שמירה מוצלחת. המידע אינו נשלח בתגובת האישור לדפדפן.
- `VoteConfirmationEmail` בודק אם השליחה פעילה ואם הכתובת תקינה, ובונה בקשת JSON אל `POST https://api.brevo.com/v3/smtp/email` באמצעות `HttpClient`. מפתח הגישה נמצא בכותרת `api-key`. הוא מטפל בכשלי רשת ובתשובות כשל בלי לשנות את ההצבעה. [חוזה ה־API הרשמי](https://developers.brevo.com/docs/send-a-transactional-email).
- `VotersController` ו־`EnvelopesController` מזמינים את שירות המייל אחרי פעולת השמירה. שירות המייל מדלג על כל תוצאה שאינה הצלחה, ולכן אישור כפול אינו שולח הודעה נוספת.
- `Program.cs` מגדיר את `HttpClient`, כתובת הספק ומגבלת הזמן, ומוודא שיש שולח ומפתח כששליחה פעילה. החלפת כתובת הספק מותרת רק בסביבת `Testing`, ורק לכתובת HTTP מקומית לצורך בדיקות.
- `run-api.ps1` ממפה את הגדרות המייל מהקובץ המקומי להגדרות ASP.NET Core, ומשחזר את משתני הסביבה ביציאה.

אין תור שליחה או ניסיון חוזר אחרי הפעלה מחדש. קריסת התהליך בין Commit לשליחה עלולה להשאיר הצבעה שמורה בלי מייל, בהתאם לדרישת ניסיון יחיד. אין כאן הבטחה למסירה לתיבת הדואר.

## בדיקות

```powershell
.venv/Scripts/python.exe tests/email/test_email.py -v
```

הבדיקות מפעילות API אמיתי ב־.NET 8, MySQL במסד זמני ומדמה מקומי של Brevo. הן כוללות גם את בדיקות השלבים הקודמים. נבדקים תוכן ההודעה וכותרת הגישה, קריאת ההצבעה כנתון שכבר נשמר באמצעות חיבור מסד עצמאי, ניסיון יחיד, כפילות, הרשאות, חלונות זמן, כתובת חסרה או שגויה, כשל ספק, Timeout, Rollback, בקשות מקבילות, מייל כבוי והיעדר מפתח או פרטי נמען בלוגים.

עברו 77 בדיקות API, כולל עשר בדיקות מייל וכל בדיקות השלבים הקודמים. עברו גם 16 בדיקות אימות וטעינת נתונים ו־17 בדיקות גבולות זמן ושעון ישראל. בדפדפן נבדקו הטופס ללא מספר קלפי, הודעת הצלחה ירוקה וחיפוש חוזר עם הודעת הצבעה כפולה אדומה. במסד התרגול אומתה התוצאה `(1, 1, True, 0)` וניסיון שליחה מדומה אחד. המאגר הפעיל לא שונה לצורך הבדיקות.

ב־2026-10-11, לאחר שהמשתמש אימת את השולח והגדיר מפתח מקומי, בוצעה בדיקה אמיתית דרך שירות המייל של המערכת. בוחר סינתטי בשם "בדיקת מערכת" נרשם במסד זמני בלבד, ונשלח ניסיון אחד למייל הוועדה. Brevo קיבל את הבקשה והחזיר HTTP 201. אישור ההצבעה החזיר HTTP 200, ואישור חוזר החזיר HTTP 409 בלי ניסיון מייל נוסף ובלי שינוי ברישום. המפתח לא הופיע בלוגים. סביבת הבדיקה הוסרה והמאגר הפעיל לא שונה.

קבלת הבקשה אצל Brevo אינה מוכיחה שהמייל הגיע לתיבה. לאחר הבדיקה המשתמש דיווח שהמייל נשלח בהצלחה. בדיקות עומס וסינון ספאם אינם מכוסים בבדיקות האוטומטיות.

בעדכון נוסף ב־2026-10-11 המשתמש דיווח שהמייל נשלח בהצלחה וביקש את נושא המייל הנוכחי. נוספה חלונית HTML מסוג `dialog` לשתי הודעות ההצבעה הכפולה; JavaScript פותח אותה כאשר מתקבלת הודעת כפילות, וכפתור "סגירה" סוגר אותה בלי בקשה לשרת. הודעת השגיאה המקורית נשארת גם בראש המסך. מספר גרסה בכתובות CSS ו־JavaScript גורם לדפדפן לטעון את העדכון במקום קובץ ישן מהמטמון.

בעדכון הזה עברו שש בדיקות API ממוקדות מול מדמה מקומי: נושא המייל המדויק בהצבעת קלפי ובמעטפה כפולה, הודעות כפילות בחיפוש ובאישור, ומניעת שליחה נוספת באישורים מקבילים. בדפדפן נבדקו חלונית בחיפוש בוחר שכבר הצביע, סגירתה ושימור ההודעה במסך, וכן אישור בשני מסכים שבו הראשון ששמר מקבל הצלחה והשני מקבל את חלונית הכפילות. נרשמה הצבעה סינתטית אחת וניסיון מייל מדומה אחד. לא נשלח שוב מייל אמיתי במסגרת העדכון.
