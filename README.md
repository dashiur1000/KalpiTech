# קלפי טק

מערכת ווב לניהול רישום הצבעות בזמן אמת. המערכת בודקת את שיוך הבוחר לקלפי, מאשרת את מימוש זכות ההצבעה, שומרת את זמן ומקום ההצבעה ומציגה נתוני השתתפות לוועדת הבחירות המרכזית.

## רכיבי המערכת

| רכיב | טכנולוגיה | תפקיד |
| --- | --- | --- |
| ממשק משתמש | Frontend | מסך התחברות, מסכי קלפיות, אישור הצבעה ומסכי ועדת הבחירות |
| API משותף | ASP.NET Core | אימות התחברות, בדיקת הרשאות, חיפוש בוחרים, אישור הצבעה ופעולות הוועדה |
| מסד נתונים | MySQL | שמירת קלפיות, בוחרים ורישומי הצבעה |
| רכיב טעינת נתונים | Python | קריאת קובצי CSV, בדיקת תקינות, ניקוי וטעינה למסד הנתונים |
| שירות מייל | שירות בצד השרת באמצעות API חיצוני | שליחת אישור לבוחר לאחר שמירת ההצבעה |

כל המשתמשים פונים ל-API משותף, שמבצע כל פעולה בהתאם להרשאות המשתמש המחובר.

## התחברות והרשאות

במסך ההתחברות יש שני שדות:

1. מספר קלפי / מייל ועדת הבחירות.
2. סיסמה.

### התחברות לקלפי

מפעיל הקלפי מזין את מספר הקלפי ואת סיסמתה. השרת מאמת את פרטי ההתחברות וטוען את מספר הקלפי וסוגה מתוך נתוני המערכת.

לאחר האימות נפתח מסך קלפי רגילה או מסך קלפי נגישה, בהתאם לסוג הקלפי.

סיסמת הקלפי נשמרת כ-`PasswordHash` בטבלת `Kalpi`.

### התחברות לוועדת הבחירות המרכזית

המשתמש מזין את מייל ועדת הבחירות בתיבת מספר הקלפי ואת הסיסמה המוגדרת במערכת.

השרת מאמת את המייל והסיסמה מול פרטי חשבון הוועדה שהוגדרו במערכת. לאחר אימות מוצלח נפתח מסך ועדת הבחירות המרכזית.

### הרשאות משתמשים

| משתמש | פעולות מורשות |
| --- | --- |
| קלפי רגילה | חיפוש ואישור הצבעה של בוחרים המשויכים לקלפי המחוברת |
| קלפי נגישה | חיפוש ואישור הצבעה של כל בוחר שקיים במאגר וטרם הצביע |
| ועדת הבחירות המרכזית | טעינת נתונים, הפעלת יום הבחירות, צפייה בנתונים והזנת מעטפות כפולות |

בכל בקשה השרת מזהה את המשתמש מתוך ההתחברות המאומתת ובודק את הרשאתו לפעולה. מספר הקלפי וסוגה נקבעים מתוך פרטי החשבון המחובר.

בחיפוש ובאישור הצבעה בקלפי רגילה, השרת משווה את `People.KalpiId` למספר הקלפי של המשתמש המחובר.

פעולות הוועדה ובדיקת נעילת טעינת הנתונים נאכפות בשרת.

## מסד הנתונים

שם מסד הנתונים: `VotesDb`.

### טבלת Kalpi

| שדה | סוג נתונים | תיאור |
| --- | --- | --- |
| `KalpiId` | `INTEGER` | מפתח ראשי; מספר הקלפי |
| `KalpiType` | `VARCHAR` | סוג הקלפי: רגילה או נגישה |
| `City` | `VARCHAR` | עיר הקלפי |
| `Place` | `VARCHAR` | שם מקום ההצבעה |
| `Address` | `VARCHAR` | כתובת הקלפי |
| `PasswordHash` | `VARCHAR` | גיבוב סיסמת ההתחברות לקלפי |

### טבלת People

| שדה | סוג נתונים | תיאור | ברירת מחדל |
| --- | --- | --- | --- |
| `Id` | `VARCHAR(9)` | מפתח ראשי; מספר זהות בן תשע ספרות, כולל אפסים מובילים | — |
| `KalpiId` | `INTEGER` | מפתח זר אל `Kalpi.KalpiId`; הקלפי שאליה הבוחר משויך | — |
| `FirstName` | `VARCHAR` | שם פרטי | — |
| `LastName` | `VARCHAR` | שם משפחה | — |
| `Voted` | `BOOLEAN` | האם ההצבעה אושרה | `FALSE` |
| `EmailAddress` | `VARCHAR` | כתובת מייל אופציונלית | `NULL` |
| `VotedAt` | `DATETIME` | מועד אישור ההצבעה | `NULL` |
| `VotedIn` | `INTEGER` | מפתח זר אל `Kalpi.KalpiId`; מספר הקלפי שבה הבוחר הצביע בפועל | `NULL` |

`KalpiId` מתאר את שיוך הבוחר. `VotedIn` מתאר את הקלפי שבה בוצעה ההצבעה בפועל.

בעת אישור הצבעה מוצלח, השרת שומר יחד את `Voted = TRUE`, את מועד ההצבעה ב-`VotedAt` ואת מספר הקלפי בפועל ב-`VotedIn`.

### מצב יום הבחירות

המערכת שומרת באופן מתמשך את מצב פתיחת ההצבעה ואת מועד סיום נעילת טעינת הנתונים. ערכים אלה נשמרים גם לאחר הפעלה מחדש של השרת.

## טעינת נתונים

רכיב Python קורא את `kalpi.csv` ואת `people.csv`, בודק את תקינותם, מנקה את הנתונים ומכניס אותם לטבלאות המתאימות.

הבדיקות כוללות את מבנה העמודות, שדות החובה, המזהים, כפילויות ושיוך כל בוחר לקלפי קיימת.

### אתחול ראשון

כאשר מאגר הקלפיות והבוחרים ריק, רכיב האתחול טוען אוטומטית את הקבצים מתיקיית `Data`.

כאשר קיימים נתונים, עליית השירותים משתמשת במאגר הקיים ומשמרת את נתוני הבוחרים וההצבעות.

### טעינה יזומה

1. ועדת הבחירות בוחרת באפשרות עדכון הנתונים.
2. השרת מאמת את הרשאת הוועדה ובודק את מצב נעילת הטעינה.
3. אם הטעינה נעולה, מוצגת הודעת נעילה וחוזרים למסך הוועדה.
4. אם קיימים נתונים, מוצגת חלונית אזהרה המבקשת אישור להחלפתם. בחירת ביטול מחזירה למסך הוועדה.
5. לאחר אישור נבחרים קובץ הקלפיות וקובץ הבוחרים.
6. שני הקבצים עוברים בדיקת תקינות לפני השינוי במאגר הפעיל.
7. החלפת הנתונים מתבצעת בטרנזקציה אחת. במקרה של כשל מתבצע Rollback והמאגר הקודם נשמר בשלמותו.
8. לאחר השלמת השמירה מוצגת ההודעה **"הנתונים הוכנסו בהצלחה"**. לאחר מספר שניות חוזרים למסך הוועדה.

החלפה מלאה זמינה עבור מאגר שטרם נרשמו בו הצבעות. מאגר המכיל הצבעות נשמר כדי להגן על רישומי ההצבעה.

במהלך ההחלפה השרת מסנכרן את פעולות הטעינה, הפעלת יום הבחירות ואישור ההצבעה, כדי לשמור על עקביות הנתונים. סיסמאות הקלפיות הקיימות נשמרות בתהליך טעינת נתוני הקלפיות.

## הפעלת יום הבחירות

ועדת הבחירות לוחצת על כפתור הפעלת יום הבחירות ומאשרת את הפעולה בחלונית שנפתחת.

לאחר האישור:

- המערכת מאפשרת אישור הצבעות.
- טעינת הנתונים ננעלת למשך 36 שעות.
- מצב פתיחת ההצבעה ומועד סיום נעילת הטעינה נשמרים במערכת.

אישור הצבעה דורש יום בחירות פעיל. נעילת הטעינה למשך 36 שעות נאכפת בשרת.

## חיפוש בוחר

1. מפעיל הקלפי מתחבר למסך המתאים לקלפי שלו.
2. המפעיל מזין מספר זהות בן תשע ספרות.
3. השרת בודק את הקלט ואת קיום הבוחר במאגר. אם מספר הזהות חסר במאגר, מוצג: **"שגיאה מספר הזהות אינו במאגר"**.
4. בקלפי רגילה השרת בודק את שיוך הבוחר. אם הבוחר משויך לקלפי אחרת, מוצג: **"הבוחר אינו משתייך לקלפי זה"**.
5. בקלפי נגישה ניתן להמשיך עם כל בוחר שקיים במאגר, בהתאם למצב ההצבעה שלו.
6. אם `Voted = TRUE`, מוצג: **"הצבעה כפולה! הבוחר כבר מימש את זכות הבחירה"**.
7. אם הבוחר עומד בתנאי הקלפי וטרם הצביע, נפתח מסך אישור ההצבעה.

## אישור הצבעה

במסך האישור מוצגת ההנחיה:

> מצביע זוהה! אנא הגש לו את מעטפת ההצבעה ולאחר הכנסתה לקלפי לחץ על אישור או ביטול במקרה שאינו חפץ להצביע כרגע.

המסך נשאר פתוח עד שהמפעיל בוחר אישור או ביטול.

### ביטול

לחיצה על ביטול מחזירה למסך הקלפי המתאים ומשאירה את רשומת הבוחר במצבה הקודם.

### אישור

השרת בודק מחדש את ההתחברות, הרשאות המשתמש ומצב יום הבחירות. בקלפי רגילה הוא בודק גם את שיוך הבוחר לקלפי המחוברת.

השמירה מתבצעת בעדכון מותנה ואטומי במסד הנתונים: השינוי מתבצע רק כאשר `Voted` עדיין `FALSE`. באותה פעולה נשמרים `Voted`, `VotedAt` ו-`VotedIn`.

רק בקשה שביצעה את השינוי בהצלחה מקבלת אישור הצלחה. כך, מבין בקשות מקבילות לאותו בוחר, בקשה אחת בלבד יכולה לשנות את מצב ההצבעה מ-`FALSE` ל-`TRUE`.

| תוצאת הפעולה | תגובת המערכת |
| --- | --- |
| ההצבעה נשמרה בהצלחה | מוצג "ההצבעה נקלטה בהצלחה!" ומופעל שירות המייל |
| הבוחר כבר הצביע | מוצג "שגיאה! הבוחר כבר הצביע ככל הנראה במקום אחר" |

לאחר הפעולה חוזרים למסך שממנו התחיל התהליך:

- קלפי רגילה → מסך קלפי רגילה.
- קלפי נגישה → מסך קלפי נגישה.

## שליחת מייל אישור

לאחר שמירת ההצבעה בהצלחה, מופעל שירות ששולח את המייל באמצעות API חיצוני.

כאשר `EmailAddress` מכיל כתובת תקינה, השירות שולח אליה הודעה בנוסח:

> שלום {FirstName} {LastName}, הצבעתך נקלטה בהצלחה!

כאשר הכתובת חסרה או אינה תקינה, המערכת מדלגת על שלב המייל ומשלימה את תהליך אישור ההצבעה.

כתובת השולח ופרטי הגישה לשירות המייל מוגדרים בצד השרת בהתאם לספק ה-API.

השירות מבצע ניסיון שליחה יחיד בעקבות שמירה מוצלחת. ההצבעה נשארת שמורה גם במקרה של כשל בשליחת המייל. במסגרת התנהגות זו ייתכן שחלק מהבוחרים יקבלו אישור במסך אך המייל שלהם לא יישלח.

## מסך ועדת הבחירות המרכזית

במסך הוועדה יש חמישה כפתורים:

| כפתור | פעולה |
| --- | --- |
| עדכון נתונים לבסיס הנתונים | בחירת קובצי קלפיות ובוחרים, אימות וטעינה בהתאם לנעילת הנתונים |
| הפעלת יום הבחירות | פתיחת אפשרות אישור הצבעה ונעילת טעינת נתונים ל-36 שעות |
| צפייה בנתונים | הצגת מספרים, אחוזים וגרפים כלליים ולפי עיר |
| הזנת מעטפות כפולות | חיפוש ואישור הצבעה בדומה למסך קלפי נגישה |
| יציאה | פתיחת חלונית אישור יציאה |

### הזנת מעטפות כפולות

הוועדה משתמשת בתהליך חיפוש ואישור עם הרשאה לטפל בכל בוחר קיים. השרת בודק את קיום הבוחר ואת מצב `Voted`, ומבצע את אותו עדכון מותנה ואטומי.

ברישום ההצבעה נשמרים מועד ההצבעה ומספר הקלפי שבה הבוחר הצביע בפועל. לאחר סיום הפעולה חוזרים למסך הוועדה.

### יציאה

בחירת אישור בחלונית היציאה מסיימת את ההתחברות ומחזירה למסך הראשי. בחירת ביטול מחזירה למסך הוועדה.

## גרפים ונתוני השתתפות

מסך הנתונים מתעדכן כל חמש שניות ומציג נתונים כלליים ונתונים לפי עיר.

### נתונים כלליים

- מספר הבוחרים במאגר.
- מספר הבוחרים שהצביעו.
- אחוז הבוחרים שהצביעו מתוך כלל הבוחרים במאגר.

### נתונים לפי עיר

בחירת עיר מתבצעת באמצעות שדה חיפוש עם השלמה מתוך הערים הקיימות בנתוני הקלפיות.

לכל עיר מוצגים:

- מספר הבוחרים המשויכים לקלפיות בעיר.
- מספר הבוחרים מתוך קבוצה זו שהצביעו.
- אחוז ההשתתפות של קבוצה זו.

שיוך הבוחר לעיר נקבע דרך `People.KalpiId` ו-`Kalpi.City`. בוחר שהצביע בקלפי בעיר אחרת נספר בנתוני העיר שאליה הוא משויך.

לדוגמה, בוחר המשויך לקלפי בבית שמש והצביע בקלפי נגישה בבני ברק נכלל בנתוני ההשתתפות של בית שמש. `VotedIn` שומר את מספר הקלפי בבני ברק.

אחוז ההשתתפות בעיר מחושב כך:

**מספר הבוחרים המשויכים לעיר שהצביעו ÷ מספר כלל הבוחרים המשויכים לעיר × 100.**

כאשר מספר הבוחרים בעיר הוא אפס, מוצג "אין נתונים".

## הבהרות מאושרות לתכנון

הבהרות אלה מעדכנות את הסעיפים המתאימים לעיל:

- השרת מפותח באמצעות ASP.NET Core ו-.NET 8.0.
- מנהל הוועדה קובע את מועד תחילת הבחירות וסיומן. המערכת במצב הכנה לפני ההתחלה, פעילות ממועד ההתחלה ועד הסיום, וסיום לאחר מכן. אישור הצבעה בקלפיות מותר בזמן הפעילות בלבד.
- ניתן לקבוע ולעדכן את המועדים לפני תחילת הבחירות בלבד. לאחר ההתחלה המועדים נעולים, גם לאחר הסיום.
- נעילת טעינת הנתונים מתחילה במועד תחילת הבחירות ונמשכת 36 שעות. האיסור להחליף מאגר המכיל הצבעות נשאר בתוקף גם לאחר פקיעת הנעילה.
- הוועדה רשאית להזין מעטפות כפולות ממועד תחילת הבחירות ועד תום 36 שעות ממועד זה, גם אם פעילות הקלפיות הסתיימה. לאחר חלון זה ההזנה חסומה.
- בהזנת מעטפה כפולה הוועדה מזינה תעודת זהות ומספר קלפי הרשום על המעטפה. השרת מאמת שהקלפי קיימת ושומר את מספרה ב-VotedIn. בפעולת עובד קלפי המספר מתקבל מזהות הקלפי המאומתת בשרת.
- VotedAt הוא זמן ההזנה למערכת, גם במעטפות כפולות. הזמנים נשמרים ב-UTC ומוצגים לפי שעון ישראל.
- אימות תעודת זהות דורש תשע ספרות בלבד, ללא בדיקת ספרת ביקורת. המזהה נשמר כמחרוזת.
- Regular ו-Accessible נשמרים כערכים פנימיים; בממשק מוצגים רגילה ונגישה. העמודה הריקה ב-people.csv מיותרת ותוסר בשלב טעינת הנתונים.
- בשלב ההתחברות תיקבע ותימסר למשתמש סיסמת מנהל ראשונית. המנהל קובע את סיסמאות הקלפיות. שינוי סיסמת המנהל דורש אימות הסיסמה הנוכחית; קביעת סיסמת קלפי נגישה למנהל מחובר בלבד ואינה דורשת הזנה חוזרת של סיסמת המנהל. כל הסיסמאות נשמרות כגיבובים.
- נוסחי הודעות שאינם מוגדרים במסמך ייקבעו בעברית ברורה ועקבית במהלך המימוש. ספק המייל וכתובת השולח ייבחרו בשלב המייל.
- נתוני ההצבעה בקובץ people.csv המקורי אושרו כנתוני דוגמה ואופסו ל-FALSE ללא זמן ומקום. טעינה ראשונית מקבלת רשימת בוחרים שטרם הצביעו, ואינה מאפסת הצבעות שכבר נשמרו במסד.
- ערכי PasswordHash בקובץ הקלפיות אינם מיובאים. קלפיות חדשות נוצרות ללא סיסמה עד שהמנהל יקבע אותה; סיסמאות במאגר קיים נשמרות.

## מצב המימוש והרצה

שלב 1 כולל שרת ASP.NET Core 8, מסד MySQL ב-Docker ובדיקת חיבור ביניהם.
הוראות הרצה, הסבר הרכיבים ובדיקות ידניות נמצאים ב-[מדריך שלב 1](docs/stage-01.md).
שלב 2 מוסיף את טבלאות Kalpi, People ו-ElectionSettings, את קשרי הקלפיות ואת
אילוצי תקינות הנתונים. הוראות הקמה ובדיקות נמצאות ב-[מדריך שלב 2](docs/stage-02.md).
שלב 3 מוסיף רכיב Python שמאמת את שני קובצי ה-CSV וטוען מאגר ריק בטרנזקציה אחת.
סקריפט run-api.ps1 מפעיל את רכיב האתחול לפני השרת ומשמר מאגר קיים.
הוראות הקמת Python, הרצה ובדיקות נמצאות ב-[מדריך שלב 3](docs/stage-03.md).
שלב 4 מוסיף מסך התחברות ב-HTML/CSS/JavaScript, אימות באמצעות Cookie מוגן,
יציאה, שינוי סיסמת מנהל וקביעת סיסמת קלפי עם הרשאת מנהל בצד השרת.
טבלת AdminAccount שומרת מנהל יחיד עם Id=1, EmailAddress ו-PasswordHash.
מייל המנהל הסופי יימסר בהמשך; עד אז שם ההתחברות הזמני הוא admin@kalpitech.local.
סיסמה ראשונית נוצרת בהקמה ונמסרת בצ'אט, ואינה מתאפסת בעת הפעלה מחדש.
סיסמאות חדשות נדרשות להכיל 12 עד 128 תווים. ההתחברות תקפה עד שמונה שעות.
הוראות הרצה, הסבר המושגים ובדיקות נמצאים ב-[מדריך שלב 4](docs/stage-04.md).
שלב 5 מוסיף חיפוש בוחרים עם בדיקות שיוך ומצב הצבעה בשרת ומסך זיהוי עם ביטול.
כפתור אישור עדיין מושבת; החיפוש אינו משנה נתונים.
הוראות הרצה והסבר הרשאות נמצאים ב-[מדריך שלב 5](docs/stage-05.md).
שלב 6 מוסיף קביעת מועדים לפי שעון ישראל עם הרשאת מנהל ושמירה ב-UTC,
מצב הכנה/פעילות/סיום מחושב בשרת וחלון 36 שעות ממועד ההתחלה.
הוראות הרצה ובדיקות נמצאות ב-[מדריך שלב 6](docs/stage-06.md).
טעינה יזומה והצבעות יתווספו בשלבים הבאים.
